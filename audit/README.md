# Dino CRM 只读功能巡检

目标：遍历 CRM 的所有非操作类页面与视图，把真实界面、可读规则和现有手册逐项对照，产出一份经过证据支持的手册优化清单。

## 开始巡检前必须满足

1. **独立登录会话**
   - 可以访问 `https://crm.dinoai.ai/dino-omnicenter`。
   - 如果公司要求 VPN、SSO、短信验证码或二次验证，需要提前完成。
   - 优先使用只读测试账号；如果只能使用个人账号，巡检期间禁止任何写入操作。

2. **浏览器控制**
   - 使用独立 Chrome 配置目录，避免读取或修改日常浏览记录。
   - Chrome 以本机回环地址上的调试端口启动，只允许本机自动化连接。
   - 巡检完成后可关闭该 Chrome 实例，不影响用户原有 Chrome。

3. **只读范围确认**
   - 允许：打开菜单、切换页签、展开筛选器、查看只读详情、读取页面结构和文字、截取页面。
   - 禁止：新增、编辑、保存、提交、删除、启用/停用、绑定、导入、导出、下载、拨号、发送、重发验证码。
   - 任何弹窗出现写入风险、权限提升、付款或数据外发时立即停止并记录。

4. **数据脱敏**
   - 原始 DOM、截图和网络请求只保存到 `audit/evidence/raw/`，该目录已被 Git 忽略。
   - 进入正式报告的截图必须遮蔽邮箱、手机号、用户 ID、录音地址和令牌。
   - 不记录 Cookie、Authorization、密码、自动填充内容或本地存储中的凭证。

5. **巡检证据**
   - 每个页面至少记录：实际 URL、页面标题、可见菜单路径、页签、主要字段、按钮、规则文案、截图、巡检时间。
   - 对筛选器等只读交互，只记录交互前后变化，不提交业务表单。
   - 页面出现错误时保留错误现象、URL、时间和截图，不反复重试。

6. **变更控制**
   - 巡检先产出报告，不直接覆盖现有手册。
   - 需要修改`docs/`时，先确认每项差异来自生产页面还是文档问题。
   - 中英文内容必须成对更新，截图必须先脱敏。
   - 现有工作区中已修改的截图属于用户现有改动，不得覆盖。

## 执行阶段

1. 启动独立 Chrome 审计配置并登录 CRM。
2. 展开全部一级和二级菜单，建立实际路由树。
3. 遍历管理看板、用户、订单、销售、营销、系统管理的全部只读页签与详情。
4. 将真实页面与现有 22 篇手册逐项比对：
   - 页面是否有手册
   - 字段、筛选器、按钮、状态是否完整
   - 规则、口径、异常路径是否说明
   - 中英文页面是否一致
5. 输出 `reports/gap-analysis.md` 和 `reports/page-evidence.json`。
6. 评审通过后，再修改手册和截图。

## 停止条件

出现以下任一情况时停止当前页面巡检并记录：

- 页面跳转到登录、SSO、验证码或权限申请页。
- 必须执行写入才能继续。
- 出现支付、数据导出、外发、授权或删除确认。
- 页面连续报错、接口限流或会话即将过期。
- 页面展示了不应复制的密钥、令牌或超范围客户数据。
